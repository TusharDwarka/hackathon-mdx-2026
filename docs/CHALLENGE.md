# CHALLENGE (from the kickoff slides; every AI reads this)

Theme not chosen yet. Pick ONE:
- **Protect:** crime reporting, scam and fraud prevention, emergency alerts and trusted contacts, support for people at risk.
- **Move:** road safety, hazard reporting, public transport and Metro Express, safer travel.
- **Live Better:** budgeting and cost of living, health and clinics, access to everyday services, daily routines.

## Rules
- Start from empty. Ideas and data hunting beforehand are fine, but no pre-built code, designs or assets.
- Own PUBLIC Git repo created at 12:30, commit often, share the link via the Google Form.
- AI is allowed, but list the AI tools in the README. We are judged on what we add.
- Use at least ONE REAL dataset, and it must power a feature (no fake/placeholder data).
- Demo live. Any team member may be asked how the app works.
- Sensitive themes must be support-focused. Never identify, profile or investigate individuals.
- Surprise card: a constraint will be revealed; it must be visibly built in (not bolted on at the end).
- Deliverable is an Android APK or an Expo/test link.

- Pitch slides, maximum 6
- README: problem, user, data sources, stack, AI tools, surprise card, how to run
- Decision log of 5-10 key decisions, with times (docs/DECISIONS.md)

## Judging (10 min pitch + demo per team)
Working solution (core feature live with real data) · The problem (specific user and pain point in a Mauritian context) · Innovation (fresh angle) · Real-world impact (who runs it, what it costs, how it reaches users) · UX and design (usable without help) · Surprise card (visibly built in) · Final pitch (clear story, smooth demo, confident answers) · Tech quality (sensible choices, clean structure, steady commits).
A simple app that truly helps its user beats a slick one with a shallow idea.

## Data tips
- Good uses: look things up, map it, filter and compare, calculate, show trends.
- Budget 2-3 hours for cleaning: Mauritian data is often in PDFs or messy sheets. Note every source.
- No machine learning needed. A simple rule that works beats a model that doesn't.

## Classic mistakes
Too many features, none finished · fake/placeholder data · a vague user like "everyone in Mauritius" · bolting on the surprise card last minute · only one teammate understands the app · skipping sleep and meals.

## Open question (stack)
The deliverable must be an Android APK or Expo/test link. The playbook assumed a Next.js web app on Vercel. Decide after the idea is chosen: Expo (React Native) fits the rules most directly; a mobile-first web link only if organisers confirm a plain URL counts as a "test link".
